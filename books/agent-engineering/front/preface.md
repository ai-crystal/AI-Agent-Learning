# 前言

一个 Agent 原型可以在一个下午跑通：读一句任务、调用模型、执行工具、把结果写回上下文。演示时它看起来像一个小型助手；一旦放到真实项目里，问题立刻变多：模型超时怎么办，工具重复执行怎么办，哪个用户能看哪份文件，长任务中断后从哪里恢复，出错时怎样证明发生了什么。

这些不是模型能力问题，而是工程问题。本书讨论的是一条 Agent 从“能跑”走到“能负责”的过程。

本书不假设读者已经读过某一本特定的书。只要你知道模型 API、JSON、HTTP 和基本的 Python，就可以从运行时、工具和权限开始读。没有这些基础，也可以先读第 1 章和每章开头的任务描述，把代码当作结构化示例。

全书围绕四个问题展开：

1. **运行时**：一次任务怎样开始、推进、暂停、恢复和结束；
2. **边界**：工具能做什么，哪些动作必须先获得授权；
3. **证据**：系统怎样记录、回放和评测自己的行为；
4. **失败**：超时、重复、越权、成本失控和模型误判怎样被限制。

本书不追求列出一套“生产框架”。框架会更替，机制不会：状态机、幂等键、最小权限、trace、预算、回滚和人工接管，在任何技术栈里都需要被明确处理。

书里的公司、请求、日志、延迟和成本都是教学示例，除特别标注外不代表真实产品数据。参数是起点，不是通用最优值。每一章都尽量把“为什么需要”放在“怎么实现”之前，再用一个小系统把这些机制串起来。
