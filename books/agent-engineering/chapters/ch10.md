# 第 10 章 安全与运行手册

## 10.1 攻击面

Agent 的安全问题不只在模型输出，还包括：

- 输入内容中的提示注入；
- 工具参数注入；
- 数据外泄（图片 URL、链接、日志）；
- 越权检索和越权写入；
- 代码执行逃逸；
- 供应链和第三方工具；
- 密钥和凭据泄露。

安全设计要假设“模型可能被说服”，把重点放在限制被说服后能做什么。

## 10.2 指令和数据

把外部文档当数据，不自动当系统指令。结构标签、角色标记和分隔符有帮助，但不能保证模型永远不混淆。高风险动作必须由程序检查，而不是只靠“提示词要求”。

## 10.3 输出和外泄

禁止或在受控环境中处理：

- 自动加载的外部图片；
- 未知链接；
- 带敏感查询参数的 URL；
- 未脱敏的日志和 trace；
- 直接回显的密钥或 token。

只读 Agent 也可能泄露数据，所以要限制可读范围和网络出口。

## 10.4 运行手册

生产系统需要一份能执行的运行手册：

- 如何判断任务卡住；
- 如何取消或恢复；
- 如何回滚模型/提示/索引；
- 如何冻结某个工具；
- 如何联系人工接管；
- 如何导出和脱敏 trace；
- 什么情况下停止服务。

事故处理不是“再试一次”。先限制影响，再定位责任层，最后修复和回归。

## 10.5 复盘

复盘要回答：

1. 哪个用户/租户/任务受影响？
2. 哪个动作越权或重复？
3. 是数据、工具、模型、提示还是权限导致？
4. 有没有日志和 trace 能复现？
5. 修复后哪个评测用例能防止回归？
6. 是否需要通知、补偿或审计？

“模型不稳定”不是根因。根因必须落到可修改的机制上。

## 10.6 本章的结论

安全、可靠性和可观测性最终都汇到运行手册：系统要能在出问题时被停下来、被解释、被修复、被证明修好了。

一个 Agent 真正达到生产标准，不是因为它从不犯错，而是因为犯错时不会悄悄扩大，且团队能从证据中恢复。
