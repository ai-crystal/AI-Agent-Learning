# 第 6 章 重排序：把候选变成证据

## 6.1 召回和重排的分工

召回阶段的目标是“不要漏”，所以候选可以多而杂；生成阶段的目标是“不要被误导”，所以证据要少而准。重排序位于两者之间：

```text
查询 + 50 个候选
  → reranker
  → 8 个高相关证据
```

召回模型通常是双塔：查询和文档分别编码，再比较向量。它快，可以在百万文档上搜索，但查询和文档在编码时没有细粒度交互。

交叉编码器（cross-encoder）把查询和每个候选拼在一起，让模型逐对阅读：

```text
[CLS] 查询 [SEP] 候选文本 [SEP] → 相关性分数
```

它能看见否定词、条件、数字和上下文关系，因此通常更准，但每个候选都要一次模型前向，成本随候选数线性增长。

## 6.2 一个重排示例

假设用户问：“使用三个月后，带首年折扣的年付专业版退款要扣多少？”

召回结果（分数为教学设计）：

| 候选 | 文本摘要 | 召回分 | 重排分 |
| --- | --- | ---: | ---: |
| A | 月付套餐退款：剩余整月可退 | 0.84 | 0.12 |
| B | 年付标准退款：按未使用月份比例 | 0.82 | 0.71 |
| C | 首年折扣订单退款：扣除已使用折扣 | 0.80 | 0.94 |
| D | 企业合同退款：另行协商 | 0.78 | 0.08 |

召回阶段 A 分数最高，因为它和“退款”最相似；但用户明确是年付，A 是月付。重排器读到“月付”和“年付”的冲突，把 C 排到第一，B 作为计算规则保留，A 和 D 降级或丢弃。

这个例子说明：**重排不是对召回分数再做一次平滑，而是换一种阅读方式。** 如果重排器只看到标题或很短摘要，它也会犯同样的错误；候选文本必须包含条件、否定和数字。

## 6.3 重排器的几种形态

**交叉编码器**：查询—候选逐对打分，精度较高，适合几十到几百个候选。需要控制输入长度和批大小。

**大模型重排**：让模型输出相关性等级、排序列表或是否包含答案。灵活，但 token 成本和延迟更高，输出格式也更不稳定。

**规则/特征重排**：结合业务字段、时效、来源权威性、点击反馈和文本匹配。适合把硬约束放在模型之前或之后。

**多阶段重排**：先用便宜的小模型把 100 个候选压到 20 个，再用更贵的大模型压到 8 个。每一阶段都要有独立的召回/精度指标。

不要默认“大模型一定更好”。重排器需要判断的是查询和证据的关系，而不是写一段漂亮的解释；在一个领域上，经过标注数据训练的小交叉编码器可能更稳定、更便宜。

## 6.4 阈值和拒答

重排分数不是概率。一个 0.8 分是否足够，要看模型、训练数据和业务代价。更可靠的做法是：

1. 在验证集上观察正负样本的分数分布；
2. 设定一个保留阈值，低于阈值的候选不进入上下文；
3. 如果所有候选都低于阈值，允许系统回答“资料不足”，而不是硬选第一名；
4. 对高风险问题（金额、医疗、法律）提高阈值或要求人工确认。

拒答不是失败。把不相关片段塞给模型，往往会得到一个更自信、更难发现的错误答案。

## 6.5 多样性与去重

如果前八个候选都来自同一份文档的相邻段落，答案可能只覆盖一个角度，其他必要条款被挤掉。常见处理：

- 按 `doc_id` 限制每篇文档最多几个候选；
- 合并相邻块，避免同一段文字重复；
- 使用 MMR 等多样性策略，在相关性和覆盖度之间取平衡；
- 对“规则、例外、计算示例”分别保留证据。

多样性不能牺牲正确性。如果问题只需要一条明确规则，强行加入不同主题的段落反而会增加干扰。

## 6.6 成本和延迟

重排成本可以粗略写成：

```text
成本 ≈ 候选数 × 每次查询-文档对的计算成本
```

假设 40 个候选、每个 400 token，一次重排要处理约 16,000 token 的输入（具体取决于模型拼接方式）；如果每次都调用大模型，成本会显著高于向量检索。

优化顺序通常是：

1. 减少不必要的候选（更好的过滤、去重、每文档限额）；
2. 用更便宜的重排器做第一阶段；
3. 缓存重复查询或相同候选的分数；
4. 只对高风险或低置信度请求调用更贵的模型；
5. 根据业务延迟预算决定是否同步重排，或先返回基础结果再异步补充。

## 6.7 失败模式

**重排器只学到“主题相似”。** 训练数据里正样本都是同主题文档，模型会把“相关话题”误当成“能回答问题”。

**候选里没有正确答案。** 重排无法创造召回阶段不存在的东西；先看 Recall@k。

**输入被截断。** 只把候选前 128 token 送给重排器，恰好切掉条件或否定词。

**分数不可比。** 不同批次、不同模型版本的分数混用；需要固定版本和校准。

**过度重排。** 为了多样性或业务规则把最相关证据排到后面；需要用端到端评测检查。

## 6.8 本章的结论

重排序把“可能相关”的候选变成“值得放进上下文”的证据。它用更高的单次计算成本换取更细的相关性判断，因此必须和召回率、上下文预算、延迟一起设计。

一个可用的重排层至少要有：包含完整条件的候选文本、可校准的阈值、去重和多样性策略、独立的 Recall/Precision 评测，以及在没有足够证据时允许拒答的机制。
