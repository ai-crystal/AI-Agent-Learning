# 第 4 章 向量、嵌入与近似检索

## 4.1 嵌入做了什么

嵌入模型把一段文本映射成一个固定维度的向量：

```text
"年付套餐退款规则" → [0.012, -0.083, ..., 0.041]  # 例如 768 维
```

训练目标让语义相近的文本在向量空间里更接近。检索时，把查询也嵌入成向量，再找距离最近的文档块。

常见相似度：

- **余弦相似度**：看夹角，适合长度不同但主题相近的文本；
- **点积**：同时受方向和长度影响，某些模型训练时就按点积使用；
- **欧氏距离**：看绝对距离，使用前要确认模型和归一化方式。

不要把不同模型的分数直接比较。一个模型的 0.82 可能比另一个模型的 0.72 更不相关；分数只有和自己的候选分布、阈值一起看才有意义。

## 4.2 精确检索与近似检索

如果有 N 个向量，最直接的做法是逐个计算相似度，再取前 k 个。这就是精确最近邻。N 很小时它简单可靠；N 到了百万级，逐条计算会消耗大量时间和内存。

近似最近邻（ANN）用索引结构减少比较次数。常见的 HNSW 把向量组织成多层图，查询从粗层进入、逐层细化；IVF 先把向量分桶，只在少数桶里搜索。它们用少量召回损失换取速度和内存。

工程上要同时记录：

- `top_k`：返回多少候选；
- `ef_search`/`nprobe`：搜索范围，越大通常召回越高、延迟越大；
- 过滤条件：在搜索前还是搜索后应用；
- 索引版本：embedding 模型换了，旧向量不能混用。

“向量库很快”不是设计结论。数据规模、维度、过滤选择性、内存和并发都会改变结果，必须在自己的数据上测 P50/P95 延迟和 Recall@k。

## 4.3 过滤与权限

一个常见的错误是：先做全库向量搜索，再在结果里删掉无权文档。这样做有两个问题：

1. 无权文档占用了候选名额，真正可用的结果可能被挤出前 k；
2. 即使没有返回正文，系统也可能通过分数、数量或错误信息泄露存在性。

更稳妥的做法是把权限、租户、地区、生效日期等条件变成索引层可执行的过滤，在召回阶段就排除不可见内容。过滤字段要结构化，不要指望模型从正文里猜“这份文档属于哪个客户”。

## 4.4 embedding 模型怎么选

选择维度不只是“排行榜分数”。要一起看：

| 维度 | 要问的问题 |
| --- | --- |
| 语言 | 中文、英文、混合语言是否都覆盖 |
| 领域 | 法律、医疗、代码、表格是否有足够训练分布 |
| 长度 | 输入上限能否覆盖一个块 |
| 归一化 | 相似度是否按模型预期使用 |
| 成本 | 在线查询和离线重建索引的费用 |
| 版本 | 升级后是否需要全量重算 |
| 部署 | 云 API、私有化、延迟和数据合规 |

不要只看一个公开榜单。用自己的查询—文档对做小规模对比，特别关注否定句、数字、专有名词和长尾表达。embedding 擅长语义相近，不擅长精确编号和否定逻辑，这正是混合检索和重排要补的缺口。

## 4.5 一个候选记录

向量检索返回的不应只有分数：

```json
{
  "chunk_id": "refund-2026-3.2-01",
  "score": 0.812,
  "source": "policy-refund-2026",
  "version": "2026-07-01",
  "section": "3.2 促销年付",
  "text": "年付专业版……",
  "retrieval": "dense",
  "index": "kb-2026-10"
}
```

保留 `retrieval` 和 `index` 便于排查：某个版本索引是否漏了文档？向量召回和关键词召回各自贡献了什么？只留一个分数，后续无法定位。

## 4.6 失败模式

**语义相似但不回答问题。** “退款政策”与“退款政策常见问题”可能很近，但后者只是目录或营销文案。需要重排判断证据性。

**数字和编号。** 向量可能把“A1023”和“A1032”看成相似文本。需要关键词检索、实体过滤或结构化查询。

**否定句。** “不适用于企业合同”与“适用于企业合同”在向量空间可能很接近。需要在切块时保留完整句子，并让重排器细读。

**长文档被压成一个向量。** 一段包含多个主题的长文本，平均后语义变得模糊。切块和父子块通常比换更大的 embedding 模型更有效。

**模型升级后混用旧向量。** 新旧向量不在同一空间，距离没有意义。索引必须带 embedding 版本，升级时重建或双写切换。

## 4.7 本章的结论

向量检索解决“语义上可能相关”的召回问题。它擅长模糊表达，不擅长精确约束、权限和否定逻辑。

一个可靠的检索层至少要有：正确的切块和元数据、明确的相似度与归一化、可观测的 ANN 参数、召回前的权限过滤，以及 embedding 版本管理。下一章会用关键词检索和查询改写补上它的短板。
