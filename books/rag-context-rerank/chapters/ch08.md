# 第 8 章 多轮对话与上下文管理

## 8.1 多轮 RAG 的额外问题

单轮 RAG 的输入是一个问题；多轮 RAG 的输入是一个会话。后者多了四类状态：

- 已经确认的实体：产品、订单、地区、时间范围；
- 已经检索过的证据：哪些文档看过、哪些被否定；
- 用户的偏好和约束：语气、格式、是否需要引用；
- 未解决的问题：上一轮为什么没有回答。

如果每一轮都把整个会话重新检索一遍，成本会上升，旧问题也会干扰当前问题。如果完全不保留状态，用户说“那它呢”时，系统不知道“它”指什么。

## 8.2 查询改写与独立问题

多轮检索的第一步通常不是搜索，而是把当前话语改写成可独立检索的问题。

```text
第 1 轮用户：专业版年付怎么退款？
系统：按未使用完整月份比例……
第 2 轮用户：那如果用了首年折扣呢？
standalone_query: 专业版年付订单使用首年折扣时的退款规则
```

改写需要保留上一轮已经确认的实体，但不能把系统上一轮的错误答案当成事实。会话状态应区分：

- 用户明确说过的条件；
- 系统推断的条件；
- 检索到的证据；
- 尚未确认的假设。

高风险条件（地区、合同类型、金额）最好向用户确认，而不是由模型补全。

## 8.3 记忆的分层

多轮 RAG 可以把状态分成几层：

| 层 | 内容 | 生命周期 |
| --- | --- | --- |
| 当前轮 | 问题、检索候选、证据 | 一次请求 |
| 会话摘要 | 已确认实体、已解决问题 | 数轮或会话结束 |
| 用户偏好 | 格式、语言、权限 | 长期，需用户可控 |
| 知识库 | 文档、版本、索引 | 独立于会话 |

不要把会话摘要和知识库混在一起。摘要里的“客户说可以退”不是政策，不能作为对外回答的依据；知识库里的旧政策也不能因为用户提过就自动生效。

## 8.4 什么时候重新检索

不是每一轮都需要检索。可以参考：

- 问题引入了新实体、新产品或新地区：重新检索；
- 只是在追问上一轮证据的细节：复用已有证据，必要时补充；
- 用户要求“根据最新政策”：强制刷新，不使用缓存；
- 上一轮证据不足：换查询或换检索策略，而不是重复同一请求；
- 会话很长，早期证据可能过期：检查版本和时效。

复用证据时也要保留来源和版本。缓存键至少包含查询、过滤条件、索引版本和权限范围；否则一个用户的缓存可能被另一个租户命中。

## 8.5 压缩会话，而不是压缩事实

长会话需要摘要，但摘要应保留：

- 用户目标；
- 已确认的硬约束；
- 已排除的方案及原因；
- 未解决问题；
- 证据 ID 和版本。

不要只写“我们讨论了很多退款问题”。一段好的会话摘要应该让下一个模型调用能接着工作，而不是重新猜测。

```text
目标：确认专业版年付、使用三个月、含首年折扣的退款金额。
硬约束：中国区；订单号 A1023；政策版本 2026-07-01。
已确认：标准规则按未使用完整月份比例；折扣需扣除。
未解决：退款到账时间；是否适用促销活动的特殊条款。
证据：E1 §3.2，E2 §3.1；旧版 E4 仅作历史对照。
```

原文证据可以留在可回查的存储里，上下文中只放摘要和 ID。需要细节时再按 ID 取回。

## 8.6 失败模式

**指代消解错误。** “它”被解析成上一个提到的产品，而不是用户真正指的对象。需要展示改写结果或在不确定时追问。

**会话污染。** 早期错误答案被写进摘要，后续轮次继续引用。摘要要标注来源和置信度，允许纠正。

**缓存越权。** 相同问题不同权限的用户命中同一缓存，泄露另一租户的文档。缓存键必须包含权限范围。

**证据过期。** 上一轮引用的政策已经更新，系统仍用旧片段回答。引用要带版本，重要问题强制刷新。

**上下文膨胀。** 每轮都把全部历史带上，成本和干扰持续增加。需要摘要、证据 ID 和按需回查。

## 8.7 一个状态记录

```json
{
  "session_id": "s-1042",
  "confirmed": {
    "product": "pro",
    "billing": "annual",
    "region": "CN",
    "used_months": 3,
    "discount": "first_year"
  },
  "unresolved": ["refund_arrival_time"],
  "evidence": [
    {"id": "E1", "doc_id": "policy-refund-2026", "version": "2026-07-01"}
  ],
  "summary": "用户询问年付专业版三个月退款金额，已确认折扣条件。",
  "updated_at": "2026-11-01T10:20:00Z"
}
```

状态记录不是给模型看的全部上下文，而是系统用来决定“下一轮该检索什么、哪些事实不能再改”的依据。

## 8.8 本章的结论

多轮 RAG 的核心不是“记住更多”，而是“记住正确的状态，并在正确的时机重新检索”。

会话摘要保存目标和约束，证据保存来源和版本，缓存保存可复用的计算结果，权限贯穿所有层。一个没有状态边界的 RAG 系统，越聊越贵，也越聊越容易把旧错误当成新事实。
