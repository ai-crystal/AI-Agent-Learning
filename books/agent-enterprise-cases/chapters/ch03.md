# 第 3 章 案例：合同审阅

## 3.1 背景

虚构制造企业“远川”每年处理数千份采购、销售和服务合同。法务团队需要检查条款缺失、付款条件、违约责任、数据处理和签署主体。

Agent 的目标是**辅助初审**，不是替代法务签字：

- 抽取合同字段；
- 标出缺失或异常条款；
- 给出引用和风险等级；
- 把需要判断的条款交给人。

## 3.2 文档处理

合同可能是扫描 PDF、Word 或带修订痕迹的版本。处理链路：

```text
文件哈希 → 解析 → 页码/条款编号 → 切块
→ 条款分类 → 字段抽取 → 规则检查 → 人工复核
```

每个字段保留 `doc_id`、页码、条款号、原文和置信度。没有原文坐标的抽取结果不能直接进入审批。

## 3.3 结构化结果

```json
{
  "contract_id": "C-2026-017",
  "party": "远川（甲方）",
  "counterparty": "星海科技（乙方）",
  "payment_terms": {"value": "验收后 45 天", "page": 4, "clause": "5.2"},
  "liability_cap": {"value": "合同总额的 100%", "page": 9, "clause": "11.3"},
  "data_processing": {"present": false, "risk": "high"},
  "missing_clauses": ["数据跨境", "分包限制"],
  "needs_human": true
}
```

抽取结果必须区分“未找到”和“明确写没有”。这两个结论对法务完全不同。

## 3.4 权限和审计

合同按业务线、地区和法务组隔离。Agent 只能读取当前审阅任务关联的合同；下载、导出、分享都要审计。模型不能把一份合同的条款带到另一份合同。

人工修改要保留原值、修改值、修改人和理由；否则无法追踪责任。

## 3.5 失败模式

- OCR 把金额/日期识别错；
- 表格条款被切断；
- 附件没有纳入；
- 修订版本取错；
- 把“无此条款”误判为“符合”；
- 过度自信，没有标出需要人工判断的例外。

高风险合同应强制人工复核，Agent 只提供清单和证据。

## 3.6 验收

- 字段抽取准确率（按字段统计）；
- 关键条款召回率；
- 漏检造成的风险；
- 人工修改率；
- 审阅时长；
- 审计记录完整率。

合同项目不能只追求“自动通过率”。把风险条款自动放过，是最危险的优化方向。
