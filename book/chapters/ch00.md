# 第 0 章 预备：这些词到底指什么

这本书里会反复出现一批词：服务器、接口、请求、JSON、进程、命令行、容器、向量、token、上下文窗口。它们大多来自软件开发和运维。如果你没写过网站或后端服务，这些词听起来像行话，而后面许多机制都建在它们上面——不懂这些词，看到“agent 通过 HTTP 调用工具”就只能背下一句话，想象不出数据到底怎样流动。

这一章不涉及 AI，只把这些基础设施讲清楚。每一节的结构都一样：先说这个词指什么东西，再给一个能想象的具体场景，最后说它在书里哪一章会用到。已经熟悉的可以跳过，但建议至少扫一遍，因为后面不再解释。

## 0.1 一段程序是怎么跑起来的

你写下的 `.py` 文件只是文本。双击运行或者敲 `python xxx.py` 时，操作系统做三件事：找一个叫 python 的程序（解释器）、把它启动成一个**进程**、把这个文件的内容交给它读。

进程可以理解为"正在运行的程序"，它有自己的三样东西：

- **内存**：变量、对象都放在这里，进程一退出就没了；
- **文件描述符**：它打开了哪些文件、连了哪些网络；
- **身份**：它属于哪个用户，能用哪些权限。

一个进程启动时，操作系统会自动给它三个通道：**标准输入**（stdin，默认是键盘）、**标准输出**（stdout，默认是屏幕）、**标准错误**（stderr，也是屏幕，专门放报错）。`print()` 写的是 stdout，异常信息走的是 stderr。

这三个通道之所以重要，是因为它们可以被"接走"。把一个程序的 stdout 接到另一个程序的 stdin，就是管道：

```bash
cat access.log | grep "500" | wc -l
```

`cat` 把文件内容吐到 stdout，`grep` 从自己的 stdin 读、过滤、再吐到 stdout，`wc` 数行数。三个进程串成一条流水线，谁也不知道对方是谁。命令行工具之所以能被 agent 随意组合，靠的就是这个约定：文本进、文本出、出错走 stderr。

书里第二章那个 agent 循环、第九章的代码执行、第十一章的沙箱，底层都是这个模型。

## 0.2 客户端与服务器：为什么模型常常不在你的电脑上

你手机上的外卖 App 不自己做菜。它把你的订单发给美团/饿了么的机房，机房里的程序处理完，把"骑手已接单"发回来。这里的两个角色就是**客户端**（client，发起请求的一方）和**服务器**（server，等着别人来请求、处理完再回复的一方）。

一个服务器程序通常会持续运行，在一个端口上“监听”请求，再用线程、协程或其他方式并发处理。处理完，它把结果写回连接。它能同时服务多少客户端，取决于计算量、数据库、内存和网络，不存在一个固定数字。

本书讨论的大参数云端模型通常跑在服务商的机房里：它们需要大量显存、专门加速卡和持续供电散热。你的程序作为客户端，通过网络请求模型服务器。不过，“模型不在你的电脑上”不是定律——较小的模型也可以本地运行，只是能力、速度和硬件要求不同。

顺便区分两个后面会遇到的词：用户看见并操作的网页或界面叫**前端**，在服务器上处理业务规则、权限和数据的程序叫**后端**。前端常用 HTML 描述页面结构、CSS 控制样式、JavaScript 处理交互。本书的 harness 偏后端，GUI agent 则常常操作前端；运行本书的本地代码示例，不要求你先会做网页。

理解了这一点，后面很多设计就顺了。为什么模型调用有延迟？因为要走网络。为什么要按 token 计费？因为服务器算力有限。为什么会限流（返回 429）？因为同一时刻有太多客户端在排队。为什么 agent 的 harness 要处理重试和超时？因为对面是一台可能忙、可能挂、可能网线被挖断的远程机器。

## 0.3 一次 HTTP 请求里有什么

客户端和服务器之间说得最多的语言叫 HTTP。一次请求由四部分组成：

```text
POST /v1/chat/completions HTTP/1.1          ← 方法 + 路径 + 协议版本
Host: api.example.com                        ← 头：发给谁
Authorization: Bearer sk-xxxx                ← 头：我是谁（凭据）
Content-Type: application/json               ← 头：我发的是什么格式

{"model": "x", "messages": [...]}            ← 体：真正的内容
```

方法是个动词：`GET` 通常表示读取，`POST` 通常表示提交或触发处理，`PUT`/`PATCH` 常用于修改，`DELETE` 用于删除；具体语义仍以 API 文档为准。路径说明要操作哪个资源。头（header）是一堆键值对，放身份、格式、语言这类元信息。体（body）才是正文。

`Authorization` 里的 API key 是一种秘密凭据，作用类似“账号门禁卡”。持有它的人可能能以你的身份调用服务并产生费用，所以要放在服务端的环境变量或密钥管理器里，不要提交到公开仓库，也不要直接写进网页前端。

服务器回一个响应，也是四部分，最关键的是**状态码**：

- `200` 成功；
- `400` 你发的东西有问题（参数错、JSON 格式错）；
- `401` / `403` 没认证 / 没权限；
- `404` 地址不对；
- `429` 请求太频繁，被限流了；
- `500` 服务器自己出错了。

这几行在第十一章讲 harness 时会反复出现：agent 的工具调用失败，到底是"我参数写错了"（400，改参数就行）、"我没权限"（403，得找人开权限）、还是"对面挂了"（500，等一会儿重试）？分不清这三种，重试策略就会写错——对着 400 一直重试，永远也不会成功。

还有一个概念叫**超时**：客户端等太久就主动放弃。因为网络对面可能永远不回，程序不能一直挂着。第十章讲浏览器 agent 时说的"页面加载等多久"，就是这个问题的日常版本。

## 0.4 JSON：一种机器和人都能读的数据格式

服务器之间传数据，最常用的格式是 JSON。它的规则只有几条：

```json
{
  "name": "张三",
  "age": 24,
  "tags": ["同事", "羽毛球"],
  "address": {"city": "杭州", "district": "西湖区"}
}
```

花括号里是“键: 值”的配对，方括号里是有序的列表。值可以是字符串、数字、布尔值（`true`/`false`）、空值（`null`）、列表或另一个对象。JSON 的键和字符串要用双引号，不能在最后一项后随手多留逗号。

它之所以成为标准，是因为两边都能解析：人扫一眼能看懂，程序 `json.loads()` 一下就变成字典。而且它有严格的语法，少一个逗号就解析失败——这一点对 agent 特别重要，因为模型输出的 JSON 一旦语法错，程序就没法执行，只能把错误丢回去让它重写。第五章讲函数调用时，模型返回的就是这种结构：

```json
{"tool": "search", "args": {"query": "2023 诺贝尔文学奖"}}
```

顺带说一句你在书里会看到的相关词：**序列化**是把内存里的对象变成 JSON 这样的文本，**反序列化**是反过来。跨进程、跨网络传数据，都必须先序列化。

## 0.5 接口（API）和 SDK

**API**（应用程序接口）是一份约定：你能问我什么、怎么问、我会怎么答。它像餐厅的菜单——菜名、价格、能不能加辣，写清楚了，你不用进厨房也知道怎么点。

写 API 的人只需要保证"按这个格式问，就按这个格式答"，中间怎么实现是他的事。所以同一个 API 背后可以换三版实现，调用方一行代码都不用改。这是软件能大规模协作的基础。

**SDK** 是把调用 API 的细节包起来的代码库。API 是菜单，SDK 是外卖 App：你点"再来一单"，它帮你拼地址、加签名、发请求、解析响应，你只拿到一个对象。Python 里 `client.chat.completions.create(...)` 这种写法，就是 SDK。

模型 API 有一个特别的约定，你要记住，因为全书都在用：一次请求传的是一个**消息数组**，每条消息有 `role` 和 `content`：

```python
[
  {"role": "system",    "content": "你是一个严谨的助手"},
  {"role": "user",      "content": "帮我算 137×248"},
  {"role": "assistant", "content": "等于 33976"},
  {"role": "user",      "content": "那再乘以 2 呢"}
]
```

`system` 是本次对话中优先级较高的规则，`user` 是用户输入，`assistant` 是模型之前的回答。对常见的无状态模型 API 来说，服务端不会替你保留上一次调用；所谓“多轮对话”，是客户端每次把需要的历史重新拼进请求。第二章的循环、第八章的上下文管理，讲的都是怎么决定这个数组里放什么。真实 API 还可能有专门的 `tool` 消息和工具调用字段，第五章会讲到。

## 0.6 命令行、工作目录、退出码

**命令行**（shell）是一个等你敲命令的程序。你敲 `ls`，它去启动一个叫 `ls` 的进程，把结果显示在终端上。它本身不做任何事，只负责"启动进程、接好输入输出"。

三个概念会在书里反复出现：

**工作目录**（cwd）是“相对路径从哪个文件夹开始解析”。`ls` 不加参数就列当前目录，`./run.sh` 里的 `.` 指当前目录。所以“给 agent 一个工作目录”首先是在说它的默认操作位置。**它不是安全边界**：程序仍可能用 `../` 或绝对路径访问别处；真正限制访问要靠权限检查和沙箱。

**退出码**是进程结束时留下的一个数字，0 表示成功，非 0 表示失败。`if errorlevel 1` 这种写法判断的就是它。脚本串起来跑的时候（`a && b`），靠这个数字决定要不要继续。

**管道与重定向**：`>` 把 stdout 写进文件，`2>` 把 stderr 写进文件，`|` 接给下一个程序。第十二章讲常驻 agent 的日志、第九章讲代码执行器怎么收集输出，用的都是这套。

命令行对 agent 特别友好，原因在 0.1 说过：它的输入输出都是纯文本，格式几十年没变，模型在预训练时见过海量的终端会话，知道 `ls -la` 的输出长什么样、`pytest` 失败时该看哪一行。这就是第九章说"接口要自然"的实际含义。

## 0.7 容器与沙箱：给代码一间带锁的房间

agent 会写代码、会执行命令。如果它直接在你这台机器上跑，一段 `rm -rf /` 就能把系统删掉，一段死循环能把内存吃光。**沙箱**（sandbox）就是用来关住它的。

最常见的实现之一是**容器**（container）。你可以把它近似理解成“一个隔离的、用完可扔的运行环境”：它通常有自己的文件系统视图、进程列表和网络配置。容器与宿主机共享操作系统内核，也能通过挂载目录、端口和凭据与外界交换资源，所以它不是天然密不透风的保险柜。

一个容器通常这样启动：

```bash
docker run --rm -v /host/work:/work -w /work --network none python:3.12 \
       python script.py
```

逐段读：`--rm` 用完自动删；`-v` 把宿主机的 `/host/work` 挂到容器里的 `/work`；`-w` 设工作目录；`--network none` 断网；最后是要跑的命令。这个示例使用 Linux 风格路径，Windows 的挂载路径写法不同。只要挂载了 `/work`，容器内代码就能改其中的宿主文件；它不是“只能碰容器里、外面绝不受影响”。高风险任务还要限制挂载为只读、降低用户权限并控制资源。

沙箱不只隔离文件。**网络**要不要放开（放开就能把数据发出去）、**资源**要不要限制（CPU、内存、执行时间）、**凭据**给不给（给了它就能用你的身份调 API），这三件事都要单独决定。第十一章讲权限、第十六章讲安全，讲的都是这几种边界怎么划。

## 0.8 数据库、向量与"相似"

**数据库**是专门存数据、并且能快速查的程序。关系型数据库把数据放在**表**里：一张表有固定的列，每一行是一条记录。

```sql
SELECT name, price FROM products WHERE category = 'book' ORDER BY price LIMIT 10;
```

上面这句的意思是：从 products 表里挑出分类是 book 的行，只要 name 和 price 两列，按价格排序，取前十。你不需要知道它怎么找到这些行（建了索引就能很快），只需要知道"用一句话描述你要什么，它给你结果"。

**向量**是一串数字，比如 `[0.21, -0.05, 0.88, ...]`，通常几百到几千个数。它的用处是表示"意思"：把一段文字送进一个**嵌入模型**（embedding model），它吐出这样一串数；意思相近的文字，数也相近。

怎么衡量"相近"？最常用的是**余弦相似度**：把两个向量看成两支箭，算它们夹角的余弦值。方向一致是 1，垂直是 0，相反是 -1。它只关心方向，不关心长短，所以长短不一的文本也能比较。

$$\cos(\mathbf{a},\mathbf{b})=\frac{\mathbf{a}\cdot\mathbf{b}}{\lVert \mathbf{a}\rVert\,\lVert \mathbf{b}\rVert}$$

一个能按向量找相似项的数据库叫**向量库**。它和普通数据库的差别在查询方式：普通库常按明确条件查（价格小于 50），向量库按“离这个向量最近的 k 个”查。数据量大时，精确比较所有向量会很慢，因此常用 HNSW、IVF 等近似索引，用少量召回损失换取速度；具体提升取决于数据规模和参数。这就是第七章说的“近似最近邻”。

搞不清这几件事，第七章的 RAG 就只能背下来；搞清了，你会明白它为什么会有"切块""重排""过滤"这些看起来琐碎的步骤。

## 0.9 token 与上下文窗口

模型不直接处理“字”，它处理的单位叫 **token**。英文里一个 token 可能是一个词或词的一部分；中文则可能是一个字、词片段或常见词。粗略估算时，有人先按“一个汉字约 1 到 2 个 token”预估，但不同分词器差异很大，正式核算费用应使用对应模型的 tokenizer（分词器）实测。

**上下文窗口**（context window）是一次请求里模型最多能看多少 token。它包括了 0.5 里说的整个消息数组，加上模型的输出。早期是 2048，后来 8K、32K、128K，现在有百万级的。

窗口有两个实际后果。第一，超了就报错或者被截断，程序必须自己控制长度——这就是第八章"上下文工程"要解决的问题。第二，窗口里的内容越多，模型越容易忽略中间部分，而且每一轮都要重新传输、重新计费——这就是为什么"把全部历史都塞进去"是个坏主意。

还有两个词你会在书里看到：**推理**（inference）指"用训练好的模型算一次输出"，和训练相对；**采样**（sampling）指模型输出不是固定的，而是按概率随机挑，同一个输入两次结果可能不同。**温度**（temperature）就是控制这个随机性的旋钮：0 附近几乎总是选概率最高的词，1 以上更愿意选冷门的词。第三章的自洽性、第十五章的评测方差，都跟它有关。

## 0.10 一次模型调用，从头到尾

把上面这些串起来，你调用一次模型的完整过程是这样的：

1. 你的程序把消息数组、模型名、温度等参数打包成一个 JSON；
2. 用 HTTP POST 发到厂商的服务器，头里带上 API key；
3. 请求经过网络，可能排队（限流）、可能超时；
4. 服务器把 JSON 里的文本切成 token，送进模型，一个 token 一个 token 地算；
5. 每算出一个 token，可以选择立刻推回来（流式），也可以攒齐了一次性返回；
6. 你的程序收到 JSON，取出文本，或者取出模型要求调用的工具名和参数；
7. 如果要做多轮，把这次的输出追加进消息数组，回到第 1 步。

第二章那个六十行的循环，做的就是第 7 步；第四章 ReAct 讲的是"什么时候该做第 7 步"；第十一章 harness 讲的是第 1 到 6 步里所有的异常怎么处理。

## 0.11 并发、延迟与"为什么 agent 这么慢"

最后说三件和体感有关的事。

**延迟**是一次请求从发出到收到花了多久。模型调用的延迟通常在几百毫秒到几十秒之间，取决于输出长度。一个十步的任务，光网络往返就可能花掉半分钟。

**并发**是同时推进几件事。如果两个工具调用互不依赖（查北京天气、查上海天气），可以同时发出去；忽略调度等开销时，理想总耗时接近较慢的那个，而不是两个相加。第五章讲的并行工具调用、第六章的 DAG 计划，都是在利用这一点。

**异步**是等待期间不让整个程序停住。发出网络请求后，当前任务可以暂时让出执行权，程序去处理别的任务，结果回来后再继续。Python 常用 `async/await` 表达这种写法。异步不会让模型本身算得更快，主要价值是提高等待期间的利用率。

理解了这三件事，你就会明白为什么"给模型更多步骤"会让 agent 变得又慢又贵，也明白为什么第十一章要把工具超时、并发上限、预算上限当成基本配置——它们不是锦上添花，而是让一个 agent 从"能跑"变成"能一直跑"的前提。

## 0.12 代码协作与开发环境里常见的词

后面几章会以修代码任务为例，这里先把常见缩写一次说清。

- **Git**：版本控制工具，记录文件在不同时间的变化，让多人协作和回退成为可能。
- **仓库**（repository，常缩写 repo）：一个项目的文件及其版本历史。代码仓库不等于普通文件夹，它还记录“谁在什么时候改了什么”。
- **GitHub**：托管 Git 仓库并提供协作服务的平台。
- **issue**：仓库里的任务单或问题单，可以记录 bug、需求或讨论。说“修 GitHub issue”，就是根据一张任务单修改代码。
- **patch**：一组代码改动，通常以“哪些行被删掉、哪些行被新增”的差异形式表示。
- **PR**（Pull Request，拉取请求）：请求把一组改动合并进主项目，通常要经过评审和自动测试。
- **IDE**（集成开发环境）：把代码编辑、搜索、运行和调试放在一起的软件，例如 VS Code。
- **测试**：用程序检查程序。`pytest` 是 Python 常用测试工具；单元测试检查一个小函数，回归测试防止旧问题在修改后复发。
- **CI**（持续集成）：代码提交后自动运行构建、检查或测试的流程。“把评测跑进 CI”，就是让每次改动都自动接受一小批检查。

另外还有三个安装框架时会遇到的词。**依赖**是项目运行所需要的其他代码包；**虚拟环境**为不同项目隔离 Python 包版本，避免互相冲突；**环境变量**是进程启动时读到的键值配置，常用来传模型名称或 API key。把密钥写进环境变量只是避免硬编码的一种做法，不代表它自动安全，文件权限和进程权限仍需控制。
