# 前言

2020 年夏天，OpenAI 放出 GPT-3 的 API。很多人第一次用几行程序把一句话发给模型，再等它回话：它能写诗、编故事，也能把英文翻成地道的中文。它看起来很博学，却只能通过文本与世界接触。

随后几年，情况发生了变化：给模型接上循环、工具和执行环境，它就能查资料、读文件、跑测试、改代码，失败后根据真实结果调整下一步。这不等于模型参数始终没变，也不等于能力全部来自外部；真正值得注意的是，**同样的模型能力，接上不同的外部系统，能完成的任务会明显不同。**

这中间发生的变化，就是这本书要讲的东西。

## 这本书想解决什么问题

现在讲 AI Agent 的材料大致分两类。一类是产品介绍和教程，读完你会用某个框架，但不知道为什么这么设计，换个场景就不知道怎么改。另一类是论文，思路很漂亮，但每篇都在解决一个具体的小问题，读完之后你知道了一堆技巧，却拼不出一张完整的地图。

更麻烦的是，这个领域的技术栈膨胀得非常快。2022 年大家还在讨论提示词怎么写，2023 年开始讲工具调用和 ReAct，2024 年关心上下文窗口和软件工程 agent，2025 年几乎所有讨论都绕不开“harness”这个词，2026 年又出现了把 agent 当成常驻服务、通过聊天软件随时召唤的产品形态。每一层新东西都架在前一层上面。如果你从最新的一篇论文或最新的框架文档切入，看到的就是一堆没有来历的名词：为什么要有工具调用协议，为什么要把上下文压缩，为什么要给 agent 分权限，为什么多 agent 系统经常不如单 agent。

所以这本书选择从最开始讲起。不是从 2020 年讲起，而是从一个更朴素的问题讲起：一个只会预测下一个词的模型，为什么不能直接拿来做事？它到底缺什么？每补上一块缺口，就长出一代新技术。这条线索一直拉到今天，你回头看那些看起来花哨的设计，会发现它们大多是在补某一块具体的缺口。

## 给谁看

这本书不假设你有前端、后端或机器学习背景。会一点 Python 函数、列表和字典会有帮助；HTTP、JSON、命令行、容器、Git 等基础概念在第 0 章集中解释，书末还有术语表。公式旁边会说明它在表达什么，英文术语保留原文，方便继续查资料。

如果你已经做过一两个 agent 项目，前面的章节可以快速翻过，第七章之后大概更对胃口：上下文怎么管、harness 怎么设计、评测怎么做、什么时候该用多 agent、什么时候不该。如果你完全没接触过，建议按顺序读，因为后面很多设计决策的理由都埋在前面的失败案例里。

## 全书的结构

第一部分讲清楚问题是怎么出现的。第一章从一个语言模型的能力边界讲起，第二章把 agent 拆成最小骨架：循环、工具、上下文、状态。

第二部分讲单 agent 的思考与行动方式，也就是这一领域最核心的几条技术路线。第三章讲让模型显式推理的种种做法，第四章讲 ReAct 这条把推理和行动缝合起来的主线，第五章讲工具调用怎么从提示技巧变成模型能力，第六章讲规划和反思，第七章讲记忆，第八章讲上下文工程——这一章可能是全书最“工程”的一章，也是实际项目里最影响成败的一章。

第三部分讲 agent 与真实世界的接口。第九章讲用代码行动，第十章讲操作浏览器和图形界面，第十一章专门讲 harness：模型之外的那一整套系统，为什么同样的模型换个外壳，成功率能差出一倍。

第四部分讲生态、协作与训练。第十二章讲协议、产品形态、常驻式个人 agent 和常见框架；第十三章讲多 agent 系统，包括它为什么经常失败；第十四章讲怎么把 agent 能力训练进模型里。

第五部分讲怎么判断它行不行，以及怎么让它不出事。第十五章讲评测，第十六章讲安全、可靠性与几个还在展开的方向。

每一章都尽量做到两件事：一是先交代任务和动机，让你知道这个技术为了解决什么具体麻烦；二是给出能落地的实现思路，而不是停在概念上。关键结构配有图示，把哪根线连到哪里画清楚，卡住时可以回头看。

## 一点提醒

这个领域没有权威教科书，很多东西还在争论中，今天的最佳实践明年可能就被推翻。书里会尽量区分三种陈述：论文报告的事实、工程界形成的共识、以及我个人的判断。第三种我会明确说这是我的看法，你可以不同意。

如果读的过程中觉得某一段讲得太快，可以先查第 0 章和书末术语表，再重读这一段涉及的例子。书稿中的平台能力会注明核验时间；具体 API、安装方式和政策仍应以最新官方文档为准。
